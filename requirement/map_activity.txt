# Screen Requirement & Bug Fix Log: MapActivity
- Build: 251 (V1.0.27)
- Tactical Proximity Radar & Device Identification SSOT Unification:
  - Context: Deep dive analysis and comprehensive due diligence across the Tactical Proximity Radar ecosystem (Quick Scanner drawer and Header Flipper scanner) and end-to-end device identification pipeline.
  - Critical Findings & Landed Architectural Fixes:
    1. Fragmented Device Identification in Radar Views: Both `openLocateDrawer()` and `updateRadarScanner()` bypassed `DevicePresentationResolver`, displaying un-synced fallback names or `"AGENT_<ID>"` instead of resolved user identities, contact names, and hardware models.
       - *Fix:* Integrated `DevicePresentationResolver.resolveDisplayName()`, `resolveRoleString()`, and `resolveRoleColor()` into both radar views.
    2. Decoupled Radar Node Selection & Map Visibility (SOP-5 Conflict): When a device $\ge 50$m was docked in the left rail, selecting it in the radar dialog animated the camera but failed to set `activeProximityTargetId`. Consequently, SOP-5 spatial suppression kept the marker suppressed/hidden on the map canvas.
       - *Fix:* Node click in `openLocateDrawer()` and `updateRadarScanner()` now assigns `activeProximityTargetId = targetUid; activeLocateTargetUid = targetUid;`, triggers `updateAddressMarquee()`, and calls `scheduleThrottledMarkerRender()` to un-suppress the marker and render the tactical focus aura.
    3. Resilient Multi-Node Camera Framing: In `openLocateDrawer()`, clicking "🗺️ FRAME ALL" previously crashed or failed with 0 or 1 point because `LatLngBounds.Builder.build()` requires distinct points.
       - *Fix:* Added point count guard: 0 points displays a toast; 1 point executes smooth single-target zoom (17f); $\ge 2$ points executes `newLatLngBounds(bounds, padding)` wrapped in a fallback try-catch.
    4. Hardware Telemetry & Battery Bounds Guard: Added `batteryLevel >= 0 && batteryLevel <= 100` range check with `⚡Charging` fallback to prevent -1% string rendering in both radar surfaces.
    5. Role-Accented Visual Cards: Added dynamic role border colors (`cardBg.setStroke(..., roleCol)`) for instant tactical threat/team status differentiation.
  - Verification: Complete debug compilation and APK package (`jButterFly-debug.apk`, 101,501,028 bytes) and unit test source verification (`compileDebugUnitTestSources`) succeeded with 0 errors.

- Build: 250 (V1.0.26)
- Play Protect Installation Unblock & Dangerous Permission Purge:
  - Defect: Installation failed on Android devices with error "App is harmful cannot be installed".
  - RCA: The inclusion of `SEND_SMS`, `RECEIVE_SMS`, and `READ_SMS` permissions alongside a high-priority (`priority="999"`) broadcast receiver for `Telephony.SMS_RECEIVED` in `AndroidManifest.xml` matched Google Play Protect's static heuristic signature for Banking Trojans / SMS Stealers.
  - Mitigation:
    1. Purged `SEND_SMS`, `RECEIVE_SMS`, and `READ_SMS` from `AndroidManifest.xml`.
    2. Removed `TelemetrySmsReceiver` declaration and deleted the receiver file.
    3. Removed runtime SMS permission request dialog from `MapActivity.java`.
    4. Recompiled and packaged clean debug APK (`jButterFly-debug.apk`).
  - Outcome: APK installs cleanly without Play Protect "Harmful App" blocking.

- Build: 249 (V1.0.25)
- Honest RAG Telemetry & Exception Audit:
  - Context: User audit challenged prior premature "all green" claims against live operational screenshot evidence.
  - Critical Findings & Defects Isolated:
    1. RED-01 (Generic "Device" Fallback Name): Two peer devices in the floating rail and on the map canvas fell back to generic "Device" because:
       a) In `LocationRepository.kt`, profile name synchronization was wrapped inside `if (!effectiveAvatar.isNullOrEmpty() && effectiveAvatar != "butterfly")`, completely ignoring incoming names whenever a peer retained the default avatar.
       b) Shallow snapshot parsing only checked `userName` and `name`, omitting `fullName`, `displayName`, `nickname`, `owner_name`, and `model`.
       c) In `DevicePresentationResolver.kt`, SQLite lookups only tested raw deviceId without candidate fallbacks (`canonicalDevId`, `rawClean`, `hwClean`, `DeviceTable` hardware models).
    2. RED-02 (Map & Floating Dock Duplication Race): In `MapActivity.java:2486`, `scheduleThrottledMarkerRender()` was triggered BEFORE `updateFloatingDevicePanel()`. On initial launch, `distantDeviceHysteresisSet` was empty when markers were evaluated, rendering distant markers on the canvas before the rail was populated.
    3. AMBER-01 (Missing Bidirectional Name Reconciliation): In `MapActivity.java`, `reconcileDeviceAvatarsWithLocalDb()` only reconciled custom avatar IDs, never syncing human names between incoming cloud locations and SQLite.
    4. AMBER-02 (Battery Telemetry Out-of-Bounds Display): Devices in low-power Doze mode or lacking sticky battery intent reported -1, resulting in raw "-1%" string rendering in floating cards and address marquee.
    5. AMBER-03 (Tactical Stale Node Dimming Missing): Nodes stationary or offline between 6h and 48h rendered with full 1.0 opacity on the map canvas without visual stale-state feedback.
- Landed Architectural Mitigations:
  1. Decoupled Identity & Avatar Ingress: Refactored `LocationRepository.kt` to synchronize display names independently of avatar status across all JSON schema aliases (`fullName`, `displayName`, `nickname`, `owner_name`, `device_name`, `model`), automatically persisting valid names into SQLite `DeviceRepository`.
  2. Multi-Candidate SSOT Hardware Resolver: Added `getDeviceModelOrName()` in `DatabaseHelper.kt` and extended `DevicePresentationResolver.resolveDisplayName()` to check `DeviceTable` and format unresolved peers as `"Device ${shortId}"` (e.g., `"Device 4379"`), eliminating ambiguous duplicate labels.
  3. Deterministic Ingress Pipeline Ordering: Re-sequenced `MapActivity.java:2480` so `updateFloatingDevicePanel()` updates `distantDeviceHysteresisSet` BEFORE `scheduleThrottledMarkerRender()` executes.
  4. Bidirectional Name & Avatar Reconciliation: Integrated `isOnlineNameValid` vs `isLocalNameValid` cross-sync in `reconcileDeviceAvatarsWithLocalDb()`.
  5. Telemetry Range Guard: Added bounds check `(batteryLevel >= 0 && batteryLevel <= 100)` with `"⚡Charging"` fallback in floating device cards and marquee.
  6. Tactical Stale Alpha Dimming: Applied `alpha = 0.65f` in `MultiMarkerEngine.kt` for fixes older than 6 hours without active SOS.
  7. Verification: Full compilation and unit test build successful (`BUILD SUCCESSFUL in 15s` and `5s`).

- Build: 248 (V1.0.24)
- Defects & Architectural Gaps:
  1. Floating Device Panel Host Device Leak: Host self-device (`Redmi Note7`) leaked into the Left Floating Distant Device HUD rail because `isSelfDevice` identity comparison checked only UID and raw agent ID, failing against custom user nicknames and hardware model strings.
  2. Marker Doubling / Missing Spatial Topology Separation (SOP-5): Devices >=50m appeared simultaneously in the Left Floating Rail AND on the Map Canvas, causing double avatar rendering.
  3. Decoupled Camera Focus & Marker Aura: Clicking a floating rail item did not update marker suppression/highlight state on the map canvas.
  4. Main-Thread GC Churn & View Re-inflation: Calling `removeAllViews()` in `updateFloatingDevicePanel()` on every 1Hz GPS update caused high GC allocations, visual stutter, and reset expanded card states.
  5. Infinite Spiderweb Vectors: Radial anchor polylines connected to distant off-screen nodes (up to 50km away), drawing lines that sliced across the entire map canvas.
  6. Fragmented Distance Calculations: Duplicate Haversine formulas existed in `LiveMapDomainFacades.kt` instead of using the canonical `SpatialMathUtil` SSOT.
- Mitigation & OOPS MVC Architecture Fix:
  1. Multi-tier Host Identity Guard: Extended `isSelfDevice` in `updateFloatingDevicePanel()` to cross-check `CircleHostDeviceId`, `CircleHostName`, `UserNickname`, `Build.MODEL`, and `tvNickName`, completely preventing host device from leaking into the floating rail.
  2. SOP-5 Spatial Topology Separation Gate: Added `suppressDeviceIds` and `focusedDeviceId` parameters with `@JvmOverloads` in `MultiMarkerEngine.processViewModelLocations()`. When distant devices are docked in the Left Floating Rail, duplicate map markers are suppressed unless actively focused.
  3. Interactive Closed-Loop Synchronizer: Integrated `activeProximityTargetId` into `scheduleThrottledMarkerRender()`, ensuring immediate marker and aura rendering when a peer is selected from the floating rail.
  4. Zero-Churn Tag-Based View Diffing: Implemented `structureMatches` check on `floatingDevicePanel` tag (`targetSig`). If device roster composition is unchanged, updates existing TextViews, battery indicators, and status dots in-place without tearing down views.
  5. Viewport-Scoped Vector Culling: Gated `renderSpiderwebAnchors` in `MultiMarkerEngine.kt` to only draw polylines for nodes within visible projection bounds (`latLngBounds + 0.05` padding), suppressing clutter.
  6. Centralized Geodesic Math SSOT: Forwarded `PolarCoordinateTransformer.toPolar` in `LiveMapDomainFacades.kt` to singleton `SpatialMathUtil.computeDistanceBetween` by reference.
  7. Resilient Telemetry Marquee Formatting: Fixed epoch 1970 timestamp fallback and integrated `DevicePresentationResolver` into `updateAddressMarquee`.
  8. Physical Verification: Clean Gradle build passed (`BUILD SUCCESSFUL in 8s`, 0 errors).

- Build: 247 (V1.0.23)
- Defect: Side action panel buttons on right side unresponsive.
- Root Cause: In `createSmallIcon()`, calling `iv.setOnClickListener(null)` after `iv.setClickable(false)` forced `setClickable(true)` with null listener in Android View framework, causing the child ImageView to intercept touches and swallow events meant for the parent FrameLayout.
- Mitigation & OOPS MVC Architecture Fix:
  1. Injected unified `View.OnClickListener clickHandler` attached to BOTH child `ImageView` and parent `FrameLayout`.
  2. Forwarded long-clicks from child `ImageView` to parent `FrameLayout` via `iv.setOnLongClickListener(v -> frame.performLongClick())`.
  3. Physical Verification: Automated tap suite confirmed all 10 right-side action icons now trigger their respective dialogs, overlays, and actions flawlessly.
